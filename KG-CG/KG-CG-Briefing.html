What using a graph looks like

10 / 44

1Ask

“Which entitlement was this line’s usage rated under, and was it still current?”

A person types this, or a tool or dashboard asks it on their behalf.

  • a revenue-assurance analyst
  • a care agent handling a dispute
  • an automated nightly check

2The graph follows the connections

MATCH (line {msisdn:"555-0142"})
  -[:GENERATED]->(usage)
  -[:RATED_UNDER]->(old)
  -[:REPLACED_BY]->(current)
WHERE usage.eventAt >= current.validFrom
RETURN usage, old, current

In plain words: start at the line, follow generated, then rated under, then replaced by, and compare the usage event time with the replacement’s effective start. Shown here in Cypher-style syntax; ISO GQL has its own syntax and implementation support—most people never see this step.

U-5531v6v7

The traversed path returns as evidence; source, identity and event-time validity checks support the conclusion:

What a graph is—and what it is not

12 / 44

A graph is

  • a way to model data as things and named relationships
  • a data model—storable in a graph database or in ordinary tables
  • a way to keep the explanation (the path) next to the answer
  • only as good as the data and identity matching behind it

A graph is not

  • a drawing or a diagram tool
  • artificial intelligence, or a model that predicts
  • a replacement for charging, billing or entitlement systems
  • automatically correct, or free—loading, identity and governance are the real work
A graph is a modeling choice. Its value comes from connected, governed facts—not from the picture.

Graph terms, from the KG-CG course
GraphG = (V, E)
Formal
A set of vertices V and distinct edge identities E. Each directed edge has a source and target; distinct edges may share endpoints and type. A property graph also carries labels and key/value properties.
Plain
Things, and the connections between them, where a connection is a first-class object rather than a side effect of two rows sharing a value.
In an example network
Roughly two dozen network and commercial elements, and the typed connections that let you get from a subscriber to the transport link underneath their session.
In charging
Connect an account, line, usage record, plan and entitlement so a disputed charge can be traced through its evidence path.
Nodev ∈ V
Formal
A vertex bearing zero or more labels (a set, not a single value), a stable identifier, and any number of properties.
Plain
One thing you want to talk about. The label answers what kind of thing; the identifier answers which one.
In an example network
(:NRCell {id: "c-4471", band: "n78"}) — one radio cell, identified by the value the inventory system uses for it.
In charging
Represent a charging-relevant thing such as an account, line, rated usage record, plan or entitlement version.
Edgee = (u, v, type)
Formal
A connection from one node to another, carrying a type and, in a property graph, its own properties. Exactly two endpoints, both of which must exist.
Plain
A statement about two things that can itself be described: when it was last confirmed, how much it carries, how much you trust it.
In an example network
(:NRCell)-[:CARRIED_BY {confirmedAt: "14:02", source: "config"}]->(:TransportLink).
In charging
Record the typed relationship, such as a plan granting an entitlement or a usage record being rated under a version.
Traversal
Formal
Evaluation of a path expression: from a starting set of nodes, follow edges matching a pattern, optionally for a variable number of steps, and return the nodes or paths reached.
Plain
Walking the connections. The operation a graph is built to make cheap, in the way a scan is what a table is built to make cheap.
In an example network
Start at one failing session, follow USES|CARRIED_BY|DEPENDS_ON up to five steps, and collect everything that could explain the failure.
In charging
Follow named relationships from a disputed charge to the entitlement and delivery evidence that explains it.
Label
Formal
A member of a set of type tags attached to a node. A node may carry none, one, or several; the model is called a labeled property graph because labels are a set rather than a single field.
Plain
What kind of thing this is. Several can be true at once.
In an example network
(:NetworkFunction:UPF) — both labels hold, so a query for all network functions and a query for user plane functions both find it.
In charging
Mark node types such as Account, UsageRecord and Entitlement so a charging query selects the intended kind of entity.
Property
Formal
In a property graph, a key/value pair on a node or edge, with value types defined by the engine. Relationships between traversable entities are modeled as edges; RDF uses predicates and triples instead.
Plain
An attribute in a property graph. Model a value as a separate node when you need its own identity and relationships.
In an example network
{band: "n78"} is a property. A site is modeled as a node when site identity and traversals matter.
In charging
Keep values such as entitlement version, amount, source and confirmation time on the thing or relationship they describe.
Directed edge
Formal
An ordered pair: the edge runs from a source node to a target node. Direction is part of the edge's identity; it is not a rendering choice.
Plain
The relationship reads one way round. A query may traverse it backwards, with indexing and query costs that depend on the engine and graph.
In an example network
(cell)-[:CARRIED_BY]->(link). The reverse reading, "the link carries the cell", is the same edge traversed backwards, not a second edge.
In charging
Preserve who generated usage and which plan grants an entitlement; reversing those links would change a charging explanation.
Triple<s, p, o>
Formal
The unit of RDF: a subject (IRI or blank node), predicate (IRI), and object (IRI, blank node, literal, or an RDF 1.2 triple term). An RDF dataset has one default graph and may have named graphs.
Plain
One assertion with three slots. Attributes can be represented as triples whose predicate names the property.
In an example network
net:c-4471 net:carriedBy net:t-31 . and net:c-4471 net:band "n78" . are both triples.
In charging
Express a charging fact as subject, relationship and object, for example a plan GRANTS an entitlement.
IRIInternationalized Resource Identifier
Formal
A globally scoped identifier, generalizing the URI to the full Unicode range. Global scope comes from the naming scheme; global uniqueness of reference is a discipline, which is why owl:sameAs exists.
Plain
A name nobody else will accidentally use, provided you coin it in a namespace you control.
In an example network
https://example.net/ns/c-4471, abbreviated net:c-4471 once the prefix is declared.
In charging
Identify the same plan, entitlement or account unambiguously when charging data crosses systems and vocabularies.
Reification
Formal
Turning a statement into a subject so that further statements can be made about it. Classically, in RDF, by minting a node with rdf:subject, rdf:predicate and rdf:object triples pointing at the parts of the original.
Plain
A way to make statements about another statement. In a property graph, edge properties can attach simple qualifiers; more complex relationships about relationships may need a separate modeled entity.
In an example network
Saying the configuration store reported this edge, with confidence 0.95 — a claim about the edge, not about the cell or the link.
In charging
Attach source, validity and last-confirmed time to a charging relationship such as plan GRANTS entitlement.
Knowledge graph
Formal
A graph of data intended to accumulate and convey knowledge of the real world, whose nodes represent entities of interest and whose edges represent relations between them — typically accompanied by a schema or ontology defining what those types mean.
Plain
A graph with declared meaning that can connect claims to sources and support checks for conflicts when those controls are implemented.
Note
There is no single agreed definition. This description was based on Hogan et al. (2020, 2021) and states governance capabilities separately from the graph data model.
In charging
Keep the durable account, plan, entitlement and rating relationships used to test whether a charge used the right version.
Schema
Formal
A specification of the permitted types of node and edge and the properties each may carry. A descriptive schema reports the shapes present; a prescriptive schema constrains the shapes allowed.
Plain
The rules about structure. Descriptive schemas report what exists; prescriptive schemas can reject a violating load when enforced at ingestion.
In an example network
"An NRCell has exactly one parent gNB-DU, a band, and a technology." In this design, an enforced gate rejects loads that violate the declared shape.
In charging
Specify allowed charging entities, relationships and fields so a malformed plan-to-entitlement link can be rejected.
Ontology
Formal
A formal, explicit specification of a shared conceptualization: classes, properties, and axioms with model-theoretic semantics from which new statements can be entailed.
Plain
A schema that also carries logical rules, so a reasoner can derive facts nobody loaded.
In an example network
If dependsOn is declared transitive and the cell depends on a transport link that depends on an optical span, a reasoner can infer that the cell depends on the span.
In charging
Agree on what plan, entitlement, rated usage and credit mean across charging, eSIM and commercial systems.
Constraint
Formal
A condition checked against graph data. A validation process may report a violation; writes are rejected only when an ingestion policy enforces that result. SHACL checks data against chosen shapes, while OWL reasoning uses open-world semantics.
Plain
A rule that validation can check. It blocks a write only when the application uses it as an enforced ingestion gate.
In an example network
A charging record should not predate the session it bills. An enforced ingestion gate rejects a violating write; an audit-only check reports it.
In charging
Validate required source and validity fields on entitlement links, and block invalid writes where the charging ingestion policy requires it.
Provenance
Formal
A record of the entities, activities and agents involved in producing a piece of data, sufficient to assess its quality, reliability and trustworthiness. Standardized by W3C PROV.
Plain
Who said this, when, on what basis, and how much you should believe them.
In an example network
{source: "config", confirmedAt: 14:02, derivation: "asserted", confidence: 0.95} on the edge itself.
In charging
Show which catalog, rating record and timestamp support a disputed charge or an automated correction.
Identity resolution
Formal
Deciding that two or more records denote the same real-world entity, and representing that decision — by merging them behind one identifier, or by asserting an equivalence such as owl:sameAs.
Plain
Working out that these three records are one cell. Also called entity resolution, record linkage, or deduplication.
In an example network
An inventory key, a vendor distinguished name and a counter identifier, all naming one radio cell.
In charging
Match subscriber, billing, line and eSIM identifiers so usage is joined to the correct account and entitlement.
Context graph
Working
A bounded, short-lived evidence graph for an investigation or decision, covering related entities and observations across a defined time window. It anchors to durable KG facts rather than copying them wholesale.
Plain
The scratch pad for one investigation. Built on demand, treated provisionally, then retired from decisions and archived for audit.
Honest
This is not a standardized term. The structure is well established — a working memory or belief state over a reference model — and the discipline described here is what makes it useful. Expect other names in other shops.
In charging
Hold incident observations and hypotheses about a charge separately from durable plan and entitlement facts.
Anchor
Formal
A node in the context graph whose sole content is a stable reference to a knowledge-graph node, plus context-local additions. It asserts no durable facts of its own.
Plain
A pointer, not a copy. It says "this investigation is about that cell", and nothing about what the cell is.
Test
If deleting the whole context graph could lose a durable fact, you copied instead of anchoring.
In charging
Attach a revenue-assurance alert to the affected account or rated usage so the investigation starts at the right place.
Observation
Formal
A measured or reported value with observation time, source, and subject. It may describe the state of a system at a particular time.
Plain
Something that was seen, with when and by whom attached.
In an example network
"Charging-record completeness 94.1% at 13:58, reported by mediation."
In charging
Record measured charging evidence, such as a rating trace or stale-edge age, with its source and observation time.
Confidence
Formal
A score in [0, 1] on an element, decomposed here into a base from source trust and derivation, multiplied by a freshness factor from age.
Plain
How much to believe this right now. Two things move it: who said it, and how long ago.
Honest
Ordinal, not probabilistic. The tiers are ranked; the arithmetic is a ranking device. This briefing says so explicitly rather than dressing it up as Bayes.
In charging
Rank an incident assessment for review; it cannot itself authorize a re-rate or customer credit.
Half-lifet½
Formal
The elapsed time after which an element's freshness factor reaches 0.5, under exponential decay: f(Δt) = 2^(−Δt / t½).
Plain
How fast this kind of evidence goes off. A live counter goes off in minutes; a configuration change does not go off for a day.
Why
Exponential rather than a cliff, so evidence loses weight smoothly instead of a conclusion flipping the instant a threshold is crossed.
In charging
Reduce the weight of aging telemetry so an old charging observation does not dominate a new investigation.
TTLtime to live
Formal
A hard expiry after which the element is removed from consideration entirely, distinct from decay, which only reduces weight.
Plain
Decay makes evidence quieter. TTL excludes it; choose the policy that fits the evidence and risk.
In an example network
A counter reading with a five-minute half-life still carries about 3% weight after 25 minutes; a 20-minute TTL removes it instead of letting a hundred stale readings sum to something significant.
In charging
Stop using time-limited charging evidence or a hypothesis after its declared expiry.
Anchoring
Formal
Establishing a reference from a context element to a knowledge-graph node by stable identifier, so that the element inherits the node's neighborhood without copying it.
Plain
Attaching a symptom to the specific thing it is about, so the topology becomes available for free.
Depends on
Identity resolution (slide 17). An anchor to the wrong node is worse than no anchor, because it will still produce a plausible-looking answer.
In charging
Bind a charging incident to the account, line and plan it concerns before searching related evidence.
NeighborhoodN(v, k)
Formal
The set of nodes reachable from v within k steps along a specified set of edge types, together with the edges among them. Also called the k-hop neighborhood or the induced subgraph.
Plain
The relevant slice of the graph. The usual unit of "give me enough context to reason with".
In an example network
Two or three hops from the charging function, restricted to dependency and service edges. Note that k is a budget: raising it multiplies cost by the branching factor.
In charging
Limit a charging investigation to nearby account, plan, entitlement, usage and delivery relationships.
Propagation
Formal
Assigning a derived value to nodes by traversing edges from a seed set, with the value attenuated at each step. Here the value is an impact or blame weight and the traversal follows dependency direction.
Plain
Letting a symptom spread along the connections that already exist, so shared causes stand out.
Contrast
A rules engine fires the rules someone wrote. Propagation finds intersections nobody anticipated, because the paths were already in the graph.
In charging
Carry an incident scope across approved graph links without treating every connected network element as a cause.
Confluence
Formal
A node reached by propagation from two or more independent seeds. The count of distinct seeds reaching it, and their independence, is what makes it interesting.
Plain
Where separate symptoms meet. The graph's answer to "what do these two problems have in common".
Caveat
Two symptoms meeting at a node whose degree is enormous is not evidence — everything meets there. Normalizing for degree is not optional.
In charging
Compare independent rating, entitlement and eSIM evidence when several paths point to the same charging cause.
Dependency direction
Formal
The orientation in which failure propagates: from a provider to its dependents. Impact traverses against the DEPENDS_ON edge and blame traverses along it.
Plain
A broken link degrades the cells above it. A degraded cell does not break the link beneath it.
Why it matters
Get it wrong and propagation reaches everything, so every candidate list is enormous and confidence separation collapses.
In charging
Separate upstream cause from downstream symptom, such as a stale entitlement link causing wrong rating.
Hypothesis
Formal
A candidate explanation: a proposition that, if true, would account for some subset of the observations. Represented as a node in the context graph with edges to the observations it explains.
Plain
A guess with its working shown. Making it a node is what lets you attach evidence to it and rank it.
In an example network
"The quota pool behind chf-007 is exhausted" — supported by two observations, contradicted by none.
In charging
State a testable charging cause, such as plan-to-entitlement drift, before deciding on remediation.
Abduction
Formal
Inference to the best explanation. From an observation and a rule that would produce it, conclude the antecedent may hold. Not sound: it does not preserve truth, which is why the output is ranked rather than asserted.
Plain
Working backwards from a symptom to a plausible cause. What a diagnostician does, and what the worked case formalizes.
Contrast
Deduction (entailment) preserves truth. Abduction does not. Every candidate cause in this briefing inherits that limit.
In charging
Infer a likely charging cause from observed symptoms, then test it against controls and source records.
Coverage
Formal
The proportion of observed symptoms a candidate would account for: |explained| / |observed|, optionally weighted by each observation's confidence.
Plain
How much of what you saw this would explain.
Watch out
Coverage alone favors nodes upstream of everything, which is exactly what specificity exists to counteract.
In charging
Check how much of the disputed usage and affected lines a candidate explanation accounts for.
Specificity
Formal
The degree to which a candidate's explanation is distinctive — high when it accounts for the observations and few rivals do, low when many candidates account for the same set.
Plain
Does this tell me anything the others do not? A cause that explains everything distinguishes nothing.
In an example network
"The core network is degraded" has perfect coverage and no specificity. It is true, useless, and would win on coverage alone.
In charging
Prefer the candidate that explains this plan and entitlement rather than a generic charging failure.
Separation
Formal
The margin between the top-ranked candidate's score and the runner-up's: s₁ − s₂. A useful triage signal, distinct from s₁ itself; fixed source and policy checks license action.
Plain
How much better the leader is than the next one. High confidence in a two-way tie is still a tie.
In an example network
0.82 over 0.79 is a worse result than 0.71 over 0.31. This margin helps triage; fixed source and policy checks separately control action.
In charging
Compare leading candidate scores during triage while keeping action authority with fixed policy checks.
Action gate
Formal
A policy component, architecturally separate from ranking, that decides whether an action is authorized by versioned facts and policy. Model ranking is advisory; approvals, reversibility and blast-radius checks remain mandatory.
Plain
The part that says yes or no. Kept separate so you can change how bold the automation is without touching how it thinks.
Why separate
The gate is the component that can cause damage, so it deserves a different standard of review and change control than the scorer.
In charging
Apply approved source, freshness, blast-radius, rollback and credit rules before refreshing an edge or re-rating.
System of record
Formal
An authoritative source for a specified entity, attribute, or time period. Authority boundaries and identity policy must be declared; other systems may hold independent records.
Plain
Identify which source can assert each fact and how records from other systems are linked or reconciled.
In an example network
In this design, inventory owns NRCell identity. An unknown cell in the counter feed raises an ingestion alert rather than creating a cell.
In charging
Define which catalog, charging, and entitlement facts each system owns, then link records under an explicit identity policy.
Ingestion pipeline
Formal
The staged path from source extract to committed graph write: extract, normalize, resolve identity, validate against the schema, upsert, stamp provenance.
Plain
The six things that must happen to every fact before it is allowed into the graph.
Note
Identity resolution comes before validation. Validating a duplicate is wasted work, and upserting one is the defect you cannot see.
In charging
Bring rated usage, plan and entitlement records into the graph with source identity and freshness checks.
Upsert
Formal
A write that creates an element if absent and updates it if present using a declared key. Replaying the same state-setting values is idempotent; increments, appends, or changing values are not automatically so.
Plain
Use a stable key and replay the same target state to avoid duplicates. Verify concurrency and update semantics separately.
In an example network
Cypher MERGE, and its trap: merging on a pattern rather than on a key creates a new node whenever any property differs.
In charging
Refresh a plan or entitlement fact by stable ID without creating a duplicate that could mislead charging queries.
Freshness
Formal
The elapsed time since an element was last confirmed by its source — distinct from when it was created and from when the row was last written.
Plain
How long ago somebody actually checked. A nightly feed that re-confirms unchanged data is fresher than a live feed that has silently stopped.
Key point
A graph is only as current as its slowest meaningful feed for the question being asked.
In charging
Detect a plan-to-entitlement link that is 38 hours old when policy expects confirmation within one hour.
Supernode
Formal
A node with unusually high degree relative to the graph. Traversals and propagation through it can be costly or bias results unless bounded or normalized.
Plain
A highly connected node that may be important to investigate and may also make some queries expensive.
Two problems
Slow queries and false candidates. The fixes differ: bounded typed traversal for the first, degree normalization for the second.
In charging
Prevent a widely shared plan or catalog node from making a charging traversal too broad or slow.
Large language modelLLM
Formal
A model trained to predict the next token in a sequence, whose output is sampled from a probability distribution rather than looked up. Next-token generation alone does not reliably distinguish a verified fact from a plausible continuation.
Plain
Extremely good at language. Its next-token generation does not itself verify truth; reliable claims need source checks.
Consequence
Everything on slides 29–30 follows from that one sentence. It is not a criticism of the models; it is a statement of what they are.
In charging
Draft an explanation for review, while charging arithmetic, authorization and credit posting remain governed elsewhere.
Grounding
Formal
Checking each generated factual claim against supplied, retrievable sources; providing source text alone does not guarantee support.
Plain
Giving it the facts and asking only for the wording. The model writes; it does not decide.
Test
Removing supporting evidence is one useful test, but every factual claim still needs direct source comparison.
In charging
Tie a proposed charging explanation to actual rating, catalog and delivery records instead of unsupported text.
RAGretrieval-augmented generation
Formal
Retrieve documents relevant to a query, place them in the model's context, and generate an answer conditioned on them. Retrieval is typically by vector similarity over text chunks.
Plain
Look things up first, then answer. The standard pattern, and a good one.
Limit
Similarity retrieval returns text that resembles the question. Basic similarity retrieval does not directly traverse typed dependencies; iterative retrieval may recover some chains, but the links still need validation.
In charging
Retrieve relevant charging policy and case records for a draft answer, then verify citations and authority separately.
GraphRAG
Formal
Graph-informed retrieval that may use entity links, local graph paths, community summaries or hybrid text retrieval to supply context for generation.
Plain
A family of retrieval methods that use graph structure, sometimes alongside text search, before generating an answer.
Honest
An umbrella term for several distinct techniques, not one method. Ask which one someone means before agreeing to it.
In charging
Retrieve connected account, usage and entitlement paths to give a charging explanation traceable evidence.
Hallucination
Formal
Generated content that is fluent and unsupported. A model cannot reliably identify every unsupported claim from its own output; compare the claim with authoritative evidence.
Plain
Confident invention. Indistinguishable from a correct answer by inspection of the text alone.
Why grounding helps
It does not make the model truthful. It moves the factual claims to a component that can be checked, and makes an unsupported claim detectable by comparison against the supplied evidence.
In charging
Treat an invented entitlement, charge reason or credit instruction as an error requiring source verification and refusal.
Decision models and the live demos
Jevdecision model
Formal
A hosted decision model that receives state plus declared Choice, Score or Noul questions and returns typed probabilities over allowed answers, with no free text. These values require local evaluation before use.
Plain
A tool that answers multiple-choice and yes/no questions with probabilities that still need checking—nothing else.
In charging
Triage questions during a revenue-assurance alert: is this deviation real, which layer is it in, is this change related, is this comparison valid. Demo 2 shows all four.
Is not
An assistant, an agent or an authority. It never writes to the knowledge graph and never decides a re-rate, refund or credit.
Jev question typesChoice · Score · Noul
Formal
Choice selects one of up to 255 supplied options and returns a distribution; Score uses 2–10 ordered levels; Noul returns one yes probability, with no separate confidence field.
Plain
Pick one, rate it, or yes/no.
In charging
Choice: which cataloged layer is this symptom in. Noul: is this change record related. Score: how severe is the customer impact.
Is not
Open questions. If the answer cannot be listed in advance, Jev is the wrong tool.
Acceptance thresholdnamed measure ≥ t
Formal
A policy cutoff on a named measure for accepting advisory evidence; below it the stage is routed to a person. This does not authorize action.
Plain
A stated rule for when an answer can enter the evidence record without asking someone first.
In charging

4TR326 in its own structure
  • TM Forum TR326, Operationalizing Ontologies for AI-Native Autonomous Networks, v1.0.0, team approved 28 May 2026. 141 pages. Alpha maturity, pre-production, member evaluated, RAND IPR.
  • Part I — semantic foundations: network semantic communication, the gap between syntactic and semantic interoperability.
  • Part II — ontology operationalization: the Linked Open Terms methodology, an ontology factory, SHACL validation, JSON-LD runtime models.
  • Part III — architecture: the Knowledge Plane, the Semantic Knowledge Fabric, the Process Semantics Layer, and the strict TBOX / ABOX / PSL / reasoning separation.
  • Part IV — reference realization on TMFC014 Location Management, with operational flows, sequence diagrams and a Protégé ontology illustration.
  • Section 9 — next steps and runtime considerations, including the explicit list of open items.
  • Section 9.1 — proposed future work, TR326 Part 2: AI-Native Runtime and Execution Model for ODA Production. Proposed, not commissioned.
  • Relationship to IG1506: TR326 positions itself as the engineering of context where IG1506 is the theory of it — concept, architecture, execution.
5Questions to ask a vendor
  • What is the deterministic component in your decision path, and can I see its rules?
  • What does your system do when it cannot separate two candidates — and can you show me that happening?
  • What is the measured traversal cost at the target node count and the target average degree, not your demo's?
  • Which decisions are inside a real-time budget, and what is that budget in milliseconds?
  • How does the model's output reach a decision, and what would have to be true for a wrong model output to produce a wrong action?
  • Who owns the ontology, and what happens to representative data model when you ship a new version?
  • How do you resolve the same subscriber across charging, entitlement and the eSIM platform — and what is your measured error rate on that?
  • What happens to the closed loop when your reasoning layer is unavailable?
  • Which intents does your system accept, expressed in which ontology, and how does it report compliance?
  • Could your intent reports serve as billing evidence — what do they record about their sources and freshness?
6Questions to ask delivery teams
  • Which of charging promises exist only in contracts and not as objectives the network can check?
  • Which of defined objectives measure a proxy, such as record flow, rather than the promise, such as correct charging?
  • Which identifiers would have to match to prove one outcome across charging, entitlement and eSIM?
  • Where would an intent report be consumed today, and what would it have to contain to settle a dispute?
  • Which decisions on the money path could become automatic at L4, and what gate stands in front of each?
